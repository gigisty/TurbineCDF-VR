Install and configure URP

  1. Prepare a Unity 6 URP project. In Package Manager, confirm Universal RP and Unity Collections resolve without compilation errors.
  2. Import the BrazeFX package. Keep the complete Assets/BrazeFX folder together so resources, shaders, demos and editor tooling retain their references.
  3. Allow the initial import to finish. BrazeFX prepares its compute kernels once after import so cold shader compilation does not block normal Play Mode entry. If the project’s Library is rebuilt, use Tools → BrazeFX → Setup → Prepare Compute Kernels and let Unity finish before testing.
  4. Configure rendering once. Choose Tools → BrazeFX → Setup → Configure URP Renderers…. Opening a BrazeFX demo also offers this setup automatically.
  5. Review the reported renderer assets. The command adds the single Braze Render Feature to project-owned renderers referenced by URP Pipeline Assets. Existing renderer features and settings are preserved, and repeating the command does not create duplicates.
  6. Confirm the camera uses that renderer. A camera override pointing to another renderer will not receive the BrazeFX passes.

New renderer features use the performance-first Mobile preset: live/cache volumes use 96 maximum steps, 0.5 samples per voxel and half-resolution reconstruction; generated volumes use 64 maximum steps and half-resolution reconstruction. Ray jitter is 0.75 and temporal interleaving is Off. Select PC for native-resolution desktop output or Console for a lower-cost native-resolution tier. Editing an individual quality field changes the profile to Custom. These preset names do not expand version 1.0’s Windows/macOS platform support.

Experimental temporal path: Slice temporal interleaving is not enabled by any shipping preset because some Unity/URP versions can expose its rotating pixel pattern as checkerboarding. Keep it Off for release-quality output.

For luminous fire, enable HDR on the camera/pipeline and add Bloom through the project’s URP post-processing workflow.

Create a first fire or smoke effect

  1. Choose GameObject → BrazeFX → Fire → Container. The menu creates and selects a ready-to-use Container; its transform and Grid define the simulation domain.
  2. With the Container selected, choose GameObject → BrazeFX → Fire → Pyro Emitter to create it as a child. Start with a primitive source and keep it inside the Container bounds.
  3. Choose smoke, temperature and fuel/emission settings on the emitter. Add child Wind, Lift, Turbulence or Vortex components only after the basic source is visible.
  4. Select the Container’s Mobile or Realtime quality preset. Enter Play Mode and inspect the Stats HUD before raising resolution.
  5. Frame the effect through a camera using the configured URP renderer. Tune lighting, shadow and raymarch settings after the motion is stable.
Hierarchy rule: a Container gathers compatible child emitters, forces and obstacles every frame. Keeping each effect grouped under its Container makes the authored relationship obvious.

Core concepts

Container

Owns the fluid domain, solver, render proxy, quality budget and child input collection.

Emitter

Introduces smoke, heat, fire and motion from primitives, mesh surfaces, skinned meshes or fracture fragments.

Forces

Wind, turbulence, vortices, gravity, lift, jets and other focused motion controls.

Obstacle

Provides a solid collision boundary. Keep collision detail appropriate to the selected grid resolution.

Render Detail

A visual warp field that adds apparent detail without creating simulation density.

Cache

A sparse, render-ready recording for deterministic playback, scrubbing and delivery.

The solver dispatches work around active occupancy bricks, but its primary fluid state still uses 3D textures. Sparse activity reduces work; it does not make a very large grid free.

Two coordinated quality systems: Container modes control simulation, detail generation, shadows and memory ceilings. Braze Render Feature presets control the shared camera-space raymarch quality for live/cache and generated volumes.
  • Use the Container inspector’s allocation estimate before applying a larger grid.
  • Watch scheduled versus required substeps. LIMITED means the selected realtime budget is trading stability for cost.
  • Physics Reference Resolution keeps world-space motion consistent while testing different grid resolutions.
  • Profile the target desktop and GPU with the same cameras, lights, shadows, particles and simultaneous Containers used by the shipped scene.

Other BrazeFX toolsets

GPU particles
Use Braze Particle System for independent particles or connect particles to fluid motion. Each particle system retains its own duration, rate, looping, burst and spawn-shape controls.
Procedural volumes
Braze Volume creates static procedural density with field-based noise, density, remap, deformation, smoothing and spline operations, followed by baked lighting and a dedicated URP composite.
Destruction and disintegration
Voronoi fracture supports GPU impact commands, structural connectivity and optional temporary cohesive macro-chunks. Surface disintegration and spread tools provide mesh-driven effect workflows without per-fragment GameObjects.
CFD visualization
CFD scenes demonstrate boundaries, propellers, vehicles, ducts, electronics cooling and architectural flow. Treat these as visualization examples; validate numerical assumptions for any engineering use.
Motion design and splines
Cloners, instances, tracers, effectors, ribbons and spline tools cover procedural layouts and effects that do not require a fluid Container.

Bake, preview and export

Game cache clips

Add Braze Cache Baker when an effect should play in Unity without running the fluid simulation. The baker records sparse render-ready scalar fields plus velocity in the compact realtime representation. Frame Skip defaults to 2: every simulation frame still runs, but only every second frame is stored. Motion Smoothing on the Cache Player uses velocity to restore continuous movement between those stored frames.

Velocity is enabled by default because it also rebuilds Render Detail at the playing device’s own detail scale. Leave Velocity Bounds off for ordinary visual clips; enable it only when particles need motion through clear air or when a complete clear-air velocity halo is required.

Master cache

  1. Open Window → BrazeFX → Export Studio and bind the source Container.
  2. Set the complete simulation Length and the blue playback/export Region. Length, In, Out and Blend are authored in frames at the Container’s simulation rate.
  3. Choose the working-cache folder. Export Studio intentionally has one master format: lossless scalar fields plus complete velocity, with no stored high-resolution Render Detail texture. Playback, scene preview and flipbook rendering rebuild Render Detail from velocity.
  4. Start Bake Cache and allow the Studio to enter and exit Play Mode. Scrub the completed cache in Edit Mode; large recordings automatically use a memory-bounded multi-lane stream when full residency is not appropriate. Random seeks remain exact-only, active playback prefetches in its direction, and an underrun buffers instead of permanently chasing the playhead.
  5. After delivery, keep the master for deterministic retries, scrubbing and flipbooks, or use Clear Bake to remove its verified generated files.

Flipbook delivery

Select a view, projection, bounds, cell/atlas limits and PNG, TGA or EXR output. Delivery writes an atlas, JSON manifest and BrazeFlipbookAsset; Create / Update Player configures playback.

OpenVDB delivery

Select density, temperature, emission and velocity grids. The dependency-free managed exporter writes one numbered .vdb file per selected frame plus a manifest. Its default delivery folder is outside Assets, so Unity does not redundantly import every DCC frame as a project asset. The one Export Studio master is lossless and always contains velocity, making it the authoritative source for these grids.

VDB import

Add GameObject → BrazeFX → Baking → VDB Import. Choose a manifest or any numbered frame to import the sequence; a single unnumbered VDB remains a still. Imported runtime data is generated under Assets/BrazeFX Imports.

Why are cache and VDB sizes different? The Braze master is a compressed random-access playback source containing renderer-ready scalars and velocity for every stored frame. VDB is a DCC interchange sequence with independently selected sparse grids and metadata. Their compression and access goals differ, so either delivery may be larger depending on the effect and selected grids.
File safety: exports use owned staging folders and rollback. Incomplete cache streams use hidden same-volume staging so Unity does not import them. Clear Bake displays and validates the exact generated cache targets before deletion. Keep manually authored files outside generated export/cache destinations.

Troubleshooting

The effect simulates but is not visible
Run Tools → BrazeFX → Setup → Configure URP Renderers…, then confirm the camera uses one of the configured renderers and the required feature pass is enabled. If a camera overrides its renderer, configure that asset too. Also check camera culling masks and Container bounds.
Live smoke shows checkerboarding or looks too soft
Select the Braze Render Feature and choose the PC preset. Confirm Live / Cache Volumes uses Resolution Divisor 1 and Temporal Interleaving Off. Divisor 2 is a deliberate mobile/performance trade, and temporal interleaving remains experimental.
The first Play Mode entry is compiling or takes unusually long
Allow the initial package import and compute-kernel preparation to complete before entering Play Mode. After deleting or rebuilding the Library, run Tools → BrazeFX → Setup → Prepare Compute Kernels once. Normal later Play Mode entry should not repeatedly cold-compile the complete kernel set.
The project has missing assembly references
Install Unity 6-compatible Universal RP and Unity Collections packages. BrazeFX is authored for URP and directly references those assemblies.
A CFD mesh SDF kernel is unsupported
Use a supported Windows Direct3D 11 or macOS Metal project and let shader import finish. BrazeFX disables an unsupported CFD mesh-SDF bake after one actionable error instead of repeatedly dispatching an invalid kernel. Android, Web, Linux and other unqualified graphics backends are not supported in version 1.0.
A Player build reports outdated URP Global Settings
Upgrade the project-owned Universal Render Pipeline Global Settings asset with the current Unity version before building. Do not reuse or downgrade the same test project across Unity versions; create a fresh project for each compatibility check.
The Container refuses a resolution
The request exceeds the selected quality preset or the device’s texture/buffer limit. Lower the grid, select an appropriate preset, or use Custom only after measuring the complete allocation.
Motion becomes unstable or the HUD says LIMITED
Reduce forces or grid resolution, raise the allowed substep budget, or use a stricter quality mode. Required substeps above the scheduled ceiling are an explicit stability/performance trade.
VDB export is disabled
Use a supported Editor host and ensure the Export Studio master and selected grids are valid. If the session references an older scalar-only or realtime-quantized cache, bake a fresh master in the current Export Studio.
A cache cannot be found after moving the project
Keep a relative .brazecache beside its cache asset for portable in-project data. External absolute cache paths are machine-specific and must remain available.
Performance drops with several effects
Profile total grid memory, render steps, lights, shadows, particle counts and simultaneous Containers. Lower the cost of the largest domains before micro-optimizing small sources.

Before shipping a project

  • Ship BrazeFX 1.0 only on its supported Windows or macOS desktop targets. Test the exact runtime graphics API and representative GPU; Editor success alone is not a runtime certification.
  • Confirm every camera uses the intended URP Renderer and that unused renderer passes are disabled.
  • Profile peak GPU memory while the most expensive effects overlap.
  • Prefer baked/cache playback when a deterministic effect does not need live simulation.
  • Keep package third-party notices with redistributed BrazeFX content and review the project’s own asset licences.
  • Do not ship development caches, VDB sequences or exports unless the player genuinely consumes them.
